# Jarvis — фаза 1: ядро + Telegram

Личная мультиагентная система. Ты пишешь задачу в Telegram. Jarvis уточняет её, превращает в
карточку, выбирает режим, выполняет, проверяет независимым критиком другого вендора и
возвращает результат. Решения про деньги, право и необратимые действия всегда за тобой.

Архитектура и обоснования — документ «Jarvis v4 — логическая схема проекта» в Claude.

## Что есть в фазе 1

| Модуль | Файл | Что делает |
| --- | --- | --- |
| Карточка задачи | `jarvis/card.py` | Цель, образ результата, критерии, класс A/B/C, приватность, автономия, бюджет, прогноз |
| Приём задачи | `jarvis/intake.py` | Запрос → карточка или до 3 уточняющих вопросов. Перед облаком данные обезличиваются |
| Роутер | `jarvis/router.py` | Класс по правилам. Модель может поднять класс, но не опустить |
| Режимы | `jarvis/modes.py` | Solo — одна модель. Team — план, параллельные субагенты (только чтение) и сведение |
| Проверка | `jarvis/verify.py` | Чек-лист в коде + критик другого вендора с чистым контекстом. Решение принимает код |
| Оркестратор | `jarvis/orchestrator.py` | Жизненный цикл с чекпоинтами, до 2 кругов доработки, эскалация к тебе |
| Шлюз моделей | `jarvis/gateway.py` | OpenRouter и локальная модель, откаты по ролям, бюджет до вызова |
| Казначей | `jarvis/treasury.py` | Лимиты на день, месяц и задачу; учёт фактических трат |
| Память | `jarvis/memory.py` | Факты с источником, уровнем и сроком; конфликты на решение; эпизоды; кандидаты в плейбук |
| Журнал решений | `jarvis/journal.py` | Прогнозы с датой проверки, Brier, калибровка |
| Страж | `jarvis/guard.py` | Стоп, обезличивание, детектор секретов |
| Карантинный читатель | `jarvis/reader.py` | Чужие страницы → только факты (JSON); инструкции оттуда помечаются и не исполняются |
| Telegram | `jarvis/telegram.py` | Только для владельца: команды, кнопки решений, стоп |
| Проверка запуска | `jarvis/doctor.py` | Секреты (есть/нет), id моделей на OpenRouter, бот, база, поиск |
| Эталонный набор | `evals/cases.yaml`, `jarvis/evals.py` | Офлайн-проверка роутера и онлайн-прогон задач |

Уроки MMachine зашиты в код и покрыты тестами:
- при ответе 402 все вызовы встают на паузу;
- пустой ответ модели повторяется с лимитом токенов ×4;
- сломанный JSON уходит следующему кандидату;
- проверяющий видит правила владельца;
- арифметику считает код;
- задачи переживают перезапуск;
- стоп-кнопка останавливает всё.

**Чего ещё нет (следующие фазы):**
- протокол точного решения на 2–3 вендора с медианой (класс A пока идёт через Team, критика и твоё решение);
- панель;
- граф памяти Graphiti;
- плейбук через ворота эталонного набора (сейчас уроки включаешь вручную: `/promote`);
- оптимизация промптов;
- напоминания по времени;
- подключение доменов и MCP через «Разведчика».

## Приватность и безопасность

- **Обезличивание.** Перед отправкой в облачные модели из текста вырезаются email, телефоны, номера карт и счетов, адреса кошельков.
- **Приватные запросы.** Если в запросе есть паспортные данные, медицина, пароли, seed-фраза и т.п. (`router.local_only_keywords`), в облако не уходит ничего. Задача целиком выполняется локальной моделью (`local_llm_url` + `models.local`), а если её нет — Jarvis спрашивает тебя. В локальном режиме критик — та же локальная модель: независимость ниже, зато данные не покидают машину.
- **Чтение веба.** Читатель ходит только на публичные адреса, внутренняя сеть VPS закрыта. Редиректы проверяются на каждом шаге.
- **Секреты.** Ключи и токены вычищаются из логов. Ответы с похожим на секрет текстом не проходят проверку.
- **Telegram.** Бот слушает только `TELEGRAM_OWNER_ID`, попытки чужих пишутся в журнал событий.

## Команды в Telegram

| Команда | Что делает |
| --- | --- |
| любой текст | Новая задача (или ответ на уточнение, если одна задача его ждёт) |
| `/new текст` | Точно новая задача |
| `/answer T-0001 текст` | Ответ на уточнение |
| `/status` | Состояние, бюджет, Brier |
| `/tasks`, `/task T-0001` | Список задач и ход работы с ценой каждого шага |
| `/stop`, `/resume` | Остановить всё / продолжить |
| `/resume_models` | Снять паузу провайдера после пополнения OpenRouter |
| `/fact ключ = значение`, `/facts` | Записать факт о себе / посмотреть память |
| `/journal` | Прогнозы и Brier |
| `/playbook`, `/promote N`, `/reject N` | Кандидаты в плейбук |

## Запуск на VPS

### 1. Секреты (делаешь ты, около 10 минут)

Ключи в чат и в репозиторий не попадают: Jarvis берёт их из Infisical при старте.

1. В Infisical создай проект `jarvis`, окружение `prod`, и добавь три секрета:
   - `OPENROUTER_API_KEY` — отдельный ключ OpenRouter для Jarvis с лимитом $300 в месяц. В OpenRouter: Keys → Create key → задать лимит;
   - `TELEGRAM_BOT_TOKEN` — у @BotFather: `/newbot` → имя → токен;
   - `TELEGRAM_OWNER_ID` — твой числовой id; его покажет @userinfobot.
2. Создай Machine Identity `jarvis-vps` с методом Universal Auth и добавь её в проект `jarvis` с правом чтения окружения `prod`. Сохрани Client ID и Client Secret. Это делается в настройках организации и проекта Infisical; если пункты меню называются иначе, ищи «Machine Identities».
3. На VPS создай файл `/etc/jarvis/infisical.env` с четырьмя строками: `INFISICAL_CLIENT_ID`, `INFISICAL_CLIENT_SECRET`, `INFISICAL_PROJECT_ID`, `INFISICAL_ENV=prod`.

### 2. Установка

```bash
# на VPS, от root
git clone https://github.com/mmachine-sudo/jarvis.git /opt/jarvis
cd /opt/jarvis && bash deploy/install.sh
```

`install.sh` создаёт пользователя `jarvis`, окружение Python, конфиг из примера. Затем запускает
`jarvis doctor` и, если всё в порядке, включает systemd-сервис. Если `doctor` покажет ✗ у id
модели, он подскажет похожие id: поправь `config/jarvis.yaml` и запусти установку ещё раз.

На VPS MMachine Infisical уже используется. Если CLI `infisical` там всё же нет, поставь его по
официальной инструкции Infisical CLI (раздел Install для Ubuntu) и запусти `install.sh` снова.

### 3. Проверка

```bash
jarvis evals                 # офлайн, бесплатно: роутер на эталонных задачах
jarvis evals --online        # настоящие модели, примерно $0.5–2 за прогон
journalctl -u jarvis -f      # логи
```

**Ворота фазы 1:**
- 20 твоих реальных задач прошли через карточку;
- онлайн-набор проходит не меньше чем на 80%;
- нет ни одного действия без твоего подтверждения;
- стоимость видна по каждой задаче (`/task`).

## Что делается с MMachine

Полезные модули MMachine (шлюз и лимиты, пирамида проверки, журнал возвратов, `ev_math`, `mm/sim`,
тесты) переносятся сюда после проверки по правилу из документа v4: модуль не зависит от
`handlers/`, `schemes`, `departments` и покрыт тестами. В фазе 1 уроки MMachine уже перенесены
в виде кода и тестов. Сами модули перенесу, когда будет доступ к репозиторию `mmachine`.
